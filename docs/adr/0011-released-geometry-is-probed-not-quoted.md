# Released geometry is probed, not quoted

Geometry the authors released (a STEP, STL or laser-cut SVG) is a source of `kind: geometry`, pinned by sha256 like a paper, but it prints no numbers: the mini centrifuge's STEP files carry no annotation and the cell stretcher's SVG sheets no text. So it enters the ledger through a third anchor beside the quote and the figure reading, a **probe**. A probe names a body in the file and takes a value from it through a check's evaluation (a bbox, a distance or angle between datums declared on the released solid and confirmed on it or derived from such datums, or a diameter of a cylindrical face or of a circle datum, ADR-0015), and records the design value (`32.5`, not a mesh's `32.4999`). cadrev evaluates it from the file on every run and fails a probe beyond `tolerance.length` or its own `tol` (capped as a check's). Like a number word (ADR-0005) and unlike a reading (ADR-0002), it needs no human confirmation, since cadrev re-reads the file the same way every time. A body is its source id, or `<source>#<n>` in file order when the file holds several. On a cut file it is one filled region, named by a point inside it, at the scale the file declares.

A `shape` check compares a built part with its released body as a whole. It aligns them by datum pairs (built ↔ released, at least three not on one line), fails when the fit's residual exceeds `tolerance.length`, and passes when the largest distance between their surfaces, sampled on each (a Hausdorff distance), is within `tolerance.length` or a `tol` capped at 1% of the body's bbox diagonal. The report gives the worst point. For a cut file, the region is compared with the part's outline projected along a named axis. Coverage for a geometry source runs over bodies, not stated quantities: each body is compared by a shape check or skipped with a reason (the centrifuge's fit testers, its compatibility body, its arrow inlay, the rotor variant the target does not name). A probe that restates a quote is `context`, and the quote stays in scope. One that differs from it is a conflict. Where only the geometry states a value (the 45° tube-bore tilt), the probe is in scope. Where a part ships as both STEP and STL, the STEP is registered.

We rejected ledgering values read off the file as proposed, which lets the value drift from the file unnoticed and leaves the released body as evidence of nothing. We rejected calling the anchor a reading, which would put a machine-checked value in PENDING REVIEW. We rejected faces picked by index or file id, which break on re-export and are unreadable in review. We rejected automatic best-fit alignment (ICP), which can lock onto a symmetric part turned one feature over and cannot say why. We rejected symmetric-difference volume as the deviation, under which a missing chamfer and a uniform offset can score alike. A passing shape check does not count a part's params as checked, and no rule forces each param of such a part onto a probe: a proposed param there stays proposed and keeps the project from Exact, which is pressure enough where the released body does settle it.
