# cadrev poses the model; MuJoCo closes the loops

A project that declares joints exports MJCF. Motion checks are evaluated on cadrev's own geometry: cadrev poses the build123d assembly at each checked joint value and runs its distance, angle and interference checks there, so a check still compares built geometry with the ledger, never with an export. MuJoCo, a tool dependency, loads the exported MJCF and solves the closed linkage loops, which cadrev does not reimplement. MJCF over URDF because the LegClaw is underactuated, with tendons, torsion springs and closed four-bar and X-linkage loops; URDF has none of these. Mass comes from datasheets for purchased parts and from geometry times density for printed ones, and the sum is checked against the stated total.

Physics values a simulation needs and papers rarely state (damping, friction, contact parameters, often stiffness) go through `params.yaml` with a basis like every other number, but exact is judged over geometry and kinematics only, and the report counts proposed physics values separately. Otherwise no simulatable project could ever be exact. We rejected checks run inside MuJoCo alone, which would trust the export, and a solver in cadrev, which would duplicate what MuJoCo's constraints already do.
