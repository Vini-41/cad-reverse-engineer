# A count reads as a count

A count a source states (a gear's teeth, a train's planets, a spring's turns) is ledgered like any other number, and where its use expects a count it reads as a pure number, not in the project's units: COMPAct's `SSPG [25, 65, 155, 0.5, 3]` gives `z_sun` 25, not 25 mm. This amends ADR-0001, under which a value printed with no unit takes the project's units. Count joins the quantities a use expects: a mass check's `counts` and any param a gear train names as a tooth or planet count. A value printed there in a unit of another quantity is `[unit-quantity]`, and one that is not a whole number is a finding. A count is checked through what it builds and couples, never by counting teeth on the solid. An instance count (planets, springs) is compared exactly with the instances the assembly places, by a `count` check or by a mass check's `counts`, which share that rule. A tooth count derives a pitch diameter (module × teeth) that a diameter check confirms on the built gear, and a ratio the gear coupling carries.

The coverage sweep still lists a count only when a count unit follows it in the unit table, now `turns` and `teeth`. Bare integers and open-ended count nouns (`3 planets`, `12 links`) are not swept, and a count printed only as a table cell enters the ledger because a param or check uses it. **Stated quantity** keeps its definition.

We rejected sweeping every printed integer, which would flag every table cell, list position and index for a skip. We rejected a fixed list of count nouns beyond units, since no list closes over what a paper counts. We rejected leaving a unitless count in project units, which works only while nothing expects a count and would let a tooth count pass as a length. We rejected counting teeth on the built solid, which costs a mesh analysis and fails wherever a gear is modelled as its pitch cylinder.
