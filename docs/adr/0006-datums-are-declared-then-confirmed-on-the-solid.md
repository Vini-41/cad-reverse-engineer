# Datums are declared, then confirmed on the solid

model.py still declares each datum as a point, and cadrev confirms that it lies on its part's solid: on the axis of a cylindrical face, within that face's axial extent, or on a face, within `tolerance.length`; any other datum is `[datum-off-solid]`. Until #29, nothing tied a datum to the solid, so a distance check confirmed the param arithmetic that placed the datum rather than the geometry: a hole built elsewhere still passed. We chose this over finding datums from named features (a hole's axis, a face's centre), which would tie them tighter, because naming features in a build123d model is a larger design that every project would have to adopt, while confirming declared datums keeps today's model contract and catches the case that was seen. It leaves one gap: a datum on some face of the part, though not the face the source means, still passes. Finding datums from features comes back if a review finds that gap used.
