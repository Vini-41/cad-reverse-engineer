# cadrev poses the model on MuJoCo's kinematics

A project that declares joints exports MJCF. Motion checks are evaluated on cadrev's own geometry: cadrev poses the build123d assembly at each checked joint value and runs its distance, angle and interference checks there, so a check still compares built geometry with the ledger, never with an export. MuJoCo, a tool dependency, loads the exported MJCF, and the closed linkage loops are solved on its model: cadrev takes Newton steps over the passive joints on the site positions and Jacobians MuJoCo computes, so it holds no kinematics of its own and the model it poses is the one it exports. MJCF over URDF because the LegClaw is underactuated, with tendons, torsion springs and closed four-bar and X-linkage loops; URDF has none of these. Mass comes from datasheets for purchased parts and from geometry times density for printed ones, and the sum is checked against the stated total.

Physics values a simulation needs and papers rarely state (damping, friction, contact parameters, often stiffness) go through `params.yaml` with a basis like every other number, but exact is judged over geometry and kinematics only, and the report counts proposed physics values separately. Otherwise no simulatable project could ever be exact. We rejected checks run inside MuJoCo alone, which would trust the export, and a kinematic model of cadrev's own, which would duplicate MuJoCo's and could disagree with the export.
