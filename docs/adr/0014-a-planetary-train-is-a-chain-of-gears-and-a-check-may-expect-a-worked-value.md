# A planetary train is a chain of gears with one member fixed; a check may compare with a value worked out from the ledger

A planetary train with one member fixed is stated as a chain of the two-joint gears cadrev already has: sun to carrier at a ratio derived from the stated tooth counts (`z_sun / (z_sun + z_ring)` with the ring fixed), then carrier to each planet at `-z_ring / z_planet`, each planet a passive revolute joint on the carrier, so its angle is relative to the carrier and the posed model shows no teeth sliding through each other. Each gear exports as the MJCF joint equality a gear already is, and a posed check reads the ratio of each gear its pose moves a joint through (ADR-0013), so the tooth counts become checked params through the derived ratios with no new rule. A stepped planet is still one instance with one joint, coupled through the step that meshes the ring.

A train with no member fixed, a differential, cannot be a chain: its three members are tied by one relation among three joints, and a MuJoCo joint equality ties only two. It is out of reach until a device needs one, through a fixed tendon and a tendon equality.

A check compares with a value worked out from the ledger through `expect: <expr>`, in place of `evidence` and `key`: an expression over ledger values written `<entry>.<key>`, numbers and the functions a derived param may call. This is how a stated ratio reaches a posed angle check (the carrier's turn per sun turn, `360 / R1.ratio`, with "7.2:1" ledgered as `{ratio: 7.2}`) and how module and teeth reach a diameter check (`module * teeth`). Since the model's ratio comes from the counts and the expected value from the stated ratio, a wrong formula, a misread count, a sign error or a unit slip fails. An expect reads only ledger values, never params, so checks still compare with evidence and never with params; each ledger value it names counts as compared. ADR-0012 and the planetary-train decision (#101) assumed a check could compare with a worked value when no mechanism existed; `expect` is that mechanism.

Only `distance`, `angle`, `diameter`, `mass`, `stroke` and `count` checks take `expect`, the kinds that compare one evaluated value with one ledger value. Spec #103 said any check may; `bbox` compares one value per axis, `range` one per end, and `shape` and `interference` compare with no ledger value, so an expect there is `[check-config]`. A `count` check takes one because a source states a count per leg or per joint, which no instance count equals: without it such a param could only stand unchecked, six of one run's thirteen warnings.

## Considered options

- **A `trains` section** naming sun, planets, ring, carrier and which member is fixed. Rejected: with one member fixed, the chain of gears says the same thing with no new section, no new MJCF element and no new posing rule, and it covers a stepped planet unchanged. A section earns its place only with differentials, which MuJoCo cannot pose through joint equalities anyway.
- **Feeding the stated ratio into the model as the gear's ratio.** Rejected: the check would then compare the stated ratio with itself, and the tooth counts would go unchecked. The ratio is derived from the counts; the stated ratio is only an expected value.
- **A derived param as a check's expected value.** Rejected: it would let params supply expected values, so a check could confirm the model's own arithmetic. `expect` reads the ledger alone.
